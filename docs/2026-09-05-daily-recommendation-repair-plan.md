# 今日推荐：数据证据与交易判断修复计划

日期：2026-09-05。状态：计划已制定，尚未实施。

## 目标与边界

让用户准确判断候选池是否完整、市场结论是否可靠、买点是否仍有效，并建立可审计的后续效果验证。面向收盘复核及 1–6 个月持有，不发展日内交易策略。

本轮先修复事实表达和证据链，再评估策略变化。保留 `/candidates` 的候选发现职责，不恢复交易计划字段作为候选资格门槛，不恢复候选表的中线周期字段。市场 60/80 档位、推荐数量上限、板块持续性门槛及买点 +1/+3/+2 奖励暂不调整。观察池允许持续为空推荐。

本计划不授权自动部署定时任务、联网重跑、修改历史正式快照或提交代码；实施时按具体任务完成必要验证。新增字段以兼容方式接入，涉及语义变化的结果保存版本。

- `recommendation_attribution.py`、`candidate_trade_plan.py` 已存在，归因已有成本、交易日窗口和成交模拟。不能把独立维科夫回测的局限当作整个仓库缺少这些功能。

## 第一阶段：确定性修复（本轮优先交付）

### T1 — 统一扫描覆盖及降级口径（P0）

涉及：`scripts/scans/daily_candidates.py`、`scripts/scans/stock_scanner.py`；对应 `tests/test_daily_recommendation_performance.py`、`tests/test_daily_candidates.py`。

- [ ] 按唯一板块标识区分合格、已尝试、成分可用、失败、未尝试数量；Provider 重试不重复计数。
- [ ] 新增尝试覆盖率和成分可用率；后者分母为本轮应展开的合格板块，另列已尝试中的成功率。缓存只有日期和质量合格才计入可用。
- [ ] 对零分母输出不适用，避免用 100% 表示无扫描；旧字段保留兼容并说明历史含义。
- [ ] 将最终未恢复的必需数据缺失聚合到总体 degraded；重试失败但最终恢复不误判。区分正常无候选、部分数据失败、整体执行失败。
- [ ] MD、HTML、JSON 使用同一完成后的审计对象；展示缺失板块及原因，不推断全市场排名。

验收：40 合格、40 尝试、20 可用的固定样例显示尝试 100%、可用 50%、degraded；覆盖重试成功、有效缓存、超时、未尝试、零板块。原候选分数及分桶不变。

### T2 — 市场评分的数据可信度（P0）

涉及：`scripts/analysis/market_regime.py`、`scripts/scans/daily_candidates.py`；对应市场环境及候选测试。

- [ ] 为五个评分组件增加可用状态、依据日、缺失原因；缺失家数以 null/“未知”展示，真实零值保持零。
- [ ] 兼容保留旧 score，明确占位参与情况；新增按原权重计算的数据覆盖率和缺失组件列表。先不对剩余权重重新归一化。
- [ ] 增加评分可能区间：已知组件加权和为下界，上界再加缺失组件权重乘 100；标注为缺失敏感性区间，不是统计置信区间。
- [ ] 在候选策略中，新增质量信息只能维持或降低原推荐档位。区间跨越 60/80 时，以区间下界决定能证实的最高档位；完整数据时完全复用原逻辑。
- [ ] 旧缓存缺质量信息时可阅读，但标记质量未知并只观察；刷新后恢复。盘中混合评分的质量必须覆盖收盘锚和盘中输入，不能由混合后的单一分数冒充完整证据。

验收：当前样例缺失权重 35%，若报告分数未发生其他调整，区间约为 14.5–49.5，仍弱势；全缺失只观察；完整数据 59/60/79/80 边界不变；缺失数据不能新增推荐。新门控作为明确的保守行为变化写入技能和规格。

### T3 — 板块持续性采集的可诊断性（P0）

- [ ] 区分“缺历史无法判断”和“历史完整但热度不足”；覆盖不足时将热点出现次数标记为证据不足，避免 0/10 暗示十天均未上榜。
- [ ] 保留正式完整截面的来源要求；旁证数据不补正式覆盖，不以当前成分回填历史。

验收：非交易日、未收盘、完整截面、部分来源、重复运行、采集缺口均有明确状态；覆盖不足不能晋级。代码完成与真实历史积累完成分开标记。

## 第二阶段：候选判断的可解释性

- [ ] 展示严格等级、奖励理由、事件日、确认日、截至依据日的信号年龄、当前状态；时间字段取现有事件证据，不从文案推测。
- [ ] 置信度明确标注“形态识别置信度，非交易胜率”；普通 JAC 与严格三级再确认可区分。
- [ ] 新数据缺确认日期/年龄时标记 unknown，不自动当作新信号；缺年龄不发严格等级奖励，旧快照仍能读取。该兼容行为变化需独立测试及版本记录。

## 第三阶段：复用现有模块补齐效果验证（独立后续里程碑）

### T7 — 候选收益与交易收益分开归因（P1）

依赖 T4；涉及 `scripts/analysis/recommendation_attribution.py`、现有交易计划模块和归因/生命周期测试。

- [ ] 增加候选信号表现口径：按正式快照固定样本、原始排名及分桶，统计后续 5/10/20/60 交易日收益与基准差，不要求交易计划；明确它不是实际交易收益。
- [ ] 复用已有交易计划和交易归因，计划独立保存并关联快照摘要及生成时间。事后补计划不能回算为当时可交易；无计划标记未评估，不混入市场不可成交的原因统计。
- [ ] 审核并修复固定 9.5% 涨停识别，使用证券类别、规则生效日和实际涨跌停价格；未知规则标记无法确认，不能猜测可成交。
- [ ] 审核 T+1 卖出约束、停牌、跳空穿越止损、跌停无法退出、同根 K 线触达止盈止损及成本默认值。日线不能证明成交的场景披露保守假设；零成本结果不得标成扣费实盘效果。
- [ ] 保持复权口径一致并记录依据版本；所有输入按当时可得时间截断。收益窗口沿用市场交易日，禁止用个股缺失 K 线缩短窗口。
- [ ] 不原地覆盖旧归因完成结果，新增 evaluator/schema 版本并隔离保存；展示两个口径各自的样本分母、未成熟、未知及不可成交数量。

验收：无计划仍有候选表现；有事前计划才进入交易模拟；未来极端 K 线不影响过去评估；不同涨跌停规则、停牌、T+1、跳空和成本具有确定性夹具。

### T8 — 独立交易计划及策略校准（P2）

- [ ] 对具备资格的少量候选，复用计划模块输出独立单股计划；纳入公告/业绩核查、周线与盈利趋势复核、入场条件、失效位、目标、有效期及风险预算。
- [ ] 候选资格和计划可执行性独立展示；不把本阶段字段塞回候选表。仓位所需账户规模和风险偏好缺失时不伪造数值。
- [ ] 先累计正式日期及成熟样本，至少沿用已有 20 个正式日期、100 个成熟观测门槛；买点分级校准还须每级至少 100 个信号。达到门槛不等于已证明有效。
- [ ] 按时间划分训练和验证，处理同股重复信号及同日相关性；对比原策略与单项改动的 Top 3/5 超额收益、成交率、盈亏比、MAE/MFE、回撤和集中度。组合回撤必须基于明确资金及持仓路径。
- [ ] 每次只评估一项策略改动；证据不足继续标注不足，不增加奖励或放宽市场门槛。1–6 个月适用性需另外观察更长持有窗口，不能由五日胜率推断。

## 顺序、测试与发布

实施顺序：T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8。第一阶段可独立交付；T3 真实历史积累与后续开发可同时推进，不要求等待十天才继续修复。T7/T8 属于后续功能里程碑，不作为基础修复完成的前提。

每项使用固定夹具验证边界；联网烟测单独标注真实来源、时间及降级结果，不让网络不稳定成为逻辑测试的前提。测试通过后不无理由重复扩大测试范围。

修改脚本前说明影响范围。每个包含脚本改动的交付批次执行相关模块测试，并运行仓库强制门禁：

```bash
python3 .claude/skills/stock-trend/tests/test_stock_trend.py
python3 .claude/skills/stock-trend/tests/test_golden.py --diff
git diff --check
```

不得为消除失败重生成 golden；确认每项数值/输出变化符合本计划后才更新，若提交则在提交说明中解释。实施时同步 `.claude/skills/stock-trend/SKILL.md`、`.claude/specs/stock-trend-skill.md` 及优化概览，避免旧计划重新引入已移除的交易计划门槛。

回滚按任务隔离：新增展示可单独撤回；T2 质量门控、T5 未知年龄奖励变化、T7 归因版本独立记录。回滚代码不删除已保存证据、不覆盖旧正式快照；不同模型版本绩效不混算。

第一阶段完成标准：半数板块缺失不再显示完整扫描；缺市场数据不再假装中性或真实零家数；持续性缺口可定位；快照冲突可解释且历史不变；目标测试和两项门禁通过。收益提升只能在后续样本中验证，不作为尚未验证的交付承诺。

本计划及相关分析仅供学习参考，不构成任何投资建议。股市有风险，投资需谨慎。
