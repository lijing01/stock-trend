# 今日推荐高优先级问题修复计划

日期：2026-09-06。状态：待实施；本次仅制定计划，未修改业务代码。

## 目标与边界

修复两个已审查确认的问题：

1. 候选截取与扩池提前结束没有使用完整个股资格，导致观察项占用输出名额、遗漏已扫描到的合格股。
2. 同一次候选运行重复读取市场缓存，导致策略、正式快照和报告可能采用不同市场依据。

保留市场 60/80 档位、推荐上限 2/5、数据质量与板块持续性门槛、资金背离规则、短线状态门控及严格买点 +1/+3/+2 奖励。保留候选发现职责，不恢复中线周期门控或交易计划完整性门槛。盘中仍为临时结果，不写正式推荐历史。

本轮不包含观察原因展示重构、无热点空报告、集中度字段修复、收益参数校准或数据采集调度。允许保留观察项，不以补足推荐数量为由降低任何资格门槛。不承诺全市场最优排名或收益提升。

## 已确认的证据

- `daily_candidates.py:select_candidate_pool()` 只检查质量分、数据资格和板块资格，然后截取 `top`；`classify_candidates()` 才检查资金背离与 `retest_pending` / `failed_breakout`。
- 固定样例：A 质量分 90、缺少所需正向板块资金证据，B 质量分 80、证据合格；`top=1` 时只留下 A，推荐为空；不提前截去 B 时，B 可进入推荐。
- `_is_final_valid_candidate()` 同样缺少上述门槛，同时用于扩池停止及最终有效数量审计。
- `main()` 开始时加载市场缓存并形成策略；`_save_recommendation_snapshot()`、`generate_report()`、`_generate_html()` 又各自加载缓存。若复盘在扫描期间更新文件，单次运行可能出现依据混用。
- 审查时 `test_daily_candidates.py` 的 148 项测试通过，上述固定样例仍能复现。现有测试通过不代表这些入口衔接已覆盖。

## T1：统一个股资格，先确定层级再截取

涉及：`scripts/scans/daily_candidates.py`；主要测试为 `tests/test_daily_candidates.py`、`tests/test_daily_recommendation_performance.py`。路径均相对于 `.claude/skills/stock-trend/`。

### 实施步骤

1. 提取无副作用的个股资格判断，显式接收候选、最低质量分和本轮策略，作为选池、扩池计数与分桶的唯一判断来源：
   - 质量调整分达到阈值；原始分观察池准入规则保持不变。
   - `data_quality.eligible` 合格。
   - 板块满足当前持续性资格。
   - 策略要求板块正向资金证据时，必须为 `positive_verified`。
   - 短线状态不是 `retest_pending` 或 `failed_breakout`。
   - 买点奖励只用于排序，不能补足质量分或绕过任何硬门槛。
2. 明确分开“个股资格”和“市场允许的推荐层级”：全局 `observation` 或推荐名额用尽不等于个股资格失败。市场弱势时仍按个股资格计数，不能因为推荐数恒为零而无条件扫描至最大范围。
3. 在 `main()` 将固定的策略传给 `scan_sectors()`、选池和分桶流程。对完整的已扫描候选先计算个股资格与候选层级，再进行输出名额分配：合格候选优先，层内按现有优先分排序，最后由观察候选填补剩余名额。
4. 保留 `--top` 为全部输出候选数量上限，`--min-candidates` 为扩池目标，市场 2/5 为推荐桶上限。三个含义不互相替代。高分但受阻候选不能挤掉合格候选；受阻候选仍可在剩余观察名额内展示。保持既有次日确认观察的非推荐属性及分桶规则。
5. 扩池提前结束使用同一个股资格判断；扫描范围、预算、数据源熔断与最大扩池上限保持不变。允许到达上限后不足目标数，不新增隐式联网补扫机制。
6. 最终审计与扩池计数使用同一判断，但明确各自统计总体：扩池计数针对全部已扫描候选，最终计数针对截取后的输出候选，不要求二者数值相等。
7. 检查 `final_valid_count` 的所有消费者。优先保留该字段原有口径，新增明确的完整个股资格计数供本轮停止判断与审计使用，并标明两个字段含义；若必须改变原字段语义，先增加审计版本、更新消费者与测试，禁止静默改义。
8. 检查 helper 和扫描函数所有调用点及测试替身。新增策略参数必须在生产入口显式传递；必要的旧调用兼容不能使生产路径跳过新增判断。同分顺序保持确定性。

### 验收用例

- 90 分无所需资金证据、80 分证据合格、`top=1`：输出并推荐后者。
- 多只受阻高分股超过默认 `top=30`，后面仍有合格股：合格股不被提前截掉。
- 高分 `retest_pending` / `failed_breakout` 与低分合格股并存：前者不能占据后者的输出名额。
- 首批表面合格数达到扩池目标，但完整资格不足：继续下一批；下一批补足后结束。
- 弱市、数据缺失或过期策略：推荐仍为空，扩池不会仅因市场禁推荐而被迫扫描到底。
- 完整资格满足但推荐超过 2/5 上限：溢出项依原规则进入非推荐桶，输出总数不超过 `top`，代码不重复。
- 质量不足、板块不合格、资金证据不合格、回踩待确认均不能借买点奖励晋级。
- 原无阻断样例的排名、分桶及数量不变；同分重复运行顺序相同。

## T2：固定单次运行的市场上下文

涉及：`scripts/scans/daily_candidates.py`；主要测试为候选、推荐快照与推荐生命周期相关测试。

### 实施步骤

1. `main()` 在开始时只读取一次市场上下文，深复制为本轮独立值；读取失败或不存在则固定为缺失状态。由同一上下文确定依据日和市场策略，并传给板块筛选、T1 个股资格判断、正式快照及全部报告构建器。
2. 为 `_save_recommendation_snapshot()`、`generate_report()`、`_generate_html()` 增加显式上下文参数，删除其内部隐式缓存读取。盘中状态与依据日沿用本轮已确定的值，构建输出时不得重新计算策略。
3. 缺失上下文必须一直保持缺失：不能因为运行期间出现新缓存而自动恢复推荐或改变报告。若下次需要更新，重新启动完整流程。
4. 优先将上下文设为内部调用必传参数，并更新全部调用者、测试和替身。如确有对外兼容需求，可用显式 sentinel 区分“未传入”与“传入缺失”，但生产路径必须始终显式传值，不能用 `regime or load_regime_context()`。
5. JSON 保留原字段，以兼容方式增加本轮市场依据和推荐依据日，内容直接来自同一上下文；正式快照的 `market_regime` 也来自该值。不得在各输出构建器里独立拼装不同口径的依据。
6. 所有消费者只读上下文；持久化边界按需深复制。生成 MD/HTML/JSON 的顺序不得改变策略、原始上下文或分桶结果。
7. 保留正式快照不可覆盖及冲突复跑留痕机制，不改写历史文件。T1 改变候选选择行为，实施时检查模型版本及归因消费者，将新结果与旧 `daily-candidates/v2` 区分；记录实际版本变更，不仅修改展示文案。

### 验收用例

- 入口读取市场 A 后，模拟缓存切换为 B：策略、快照、MD、HTML、JSON 全部仍使用 A。
- A 为弱市、B 为强市，以及 A 为强市、B 为弱市两个方向都覆盖，推荐不能因输出阶段读缓存而改变。
- 入口缓存缺失，扫描期间出现完整强市缓存：本轮仍只观察，所有输出显示市场依据缺失。
- 通过入口测试断言每次完整运行 `load_regime_context()` 恰好调用一次；覆盖 MD+HTML、JSON+HTML、仅 JSON、仅 MD 四种路径。
- 直接调用报告与快照 helper，令缓存读取函数抛错：显式上下文仍可完成输出，证明不再隐式读取。
- 构建输出前后比较上下文、策略和分桶，验证没有原地修改。
- 盘中结果保持临时且不写正式历史；正式快照首次保存、幂等复跑、同日实质冲突与旧格式读取均保留原行为。

## 完成标准与风险

- 已扫描到的合格候选不再被高分受阻候选挤出；没有放宽任何资格门槛。
- 扩池、选池、分桶和审计共享完整个股资格判断，市场策略与个股资格分开表达。
- 一次运行的全部结果使用同一市场上下文，缺失状态也一致。
- 上述回归测试和仓库门禁通过；既有 JSON 消费者与历史快照保持可读取。
- 完整个股资格计数可能使某些运行展开更多板块、延长耗时；必须受现有预算与上限约束，并在性能测试中覆盖，不能通过恢复错误计数规避。
- 回滚只回滚代码与接口变更，不删除已生成证据、不覆盖正式快照；不同模型版本的结果不能混作同一策略收益。
