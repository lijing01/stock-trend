# 今日推荐：新闻融合与加减分溯源计划

日期：2026-09-12。本文为实施计划，不代表功能已经完成。

## 目标与范围

在现有今日推荐中，让每只候选同时展示量化加减分、维科夫加减分、新闻加减分及各自来源，并能从明细复算总分。本计划将“加减法”解释为评分贡献与调整，不解释为交易加减仓。

首阶段完成新闻与推荐报告的融合，保留现有新闻影子模式；新闻改变正式排序作为后续独立阶段，以前向验证结果和明确的策略发布决定为依据。

## 已确认的现状

- `bridge/run_today.py` 的今日推荐已有新闻影子层；`fetchers/candidate_news.py` 获取巨潮公告和东方财富个股新闻。
- `core/candidate_news.py` 使用关键词、来源折扣、时间衰减及 [-3,+1] 封顶，记录新闻影子排序，不改变正式推荐。
- `scans/stock_scanner.py` 已输出原始维度、综合分、覆盖率及新鲜度折扣后的质量分。
- `scans/daily_candidates.py` 在质量分之上添加严格维科夫买点奖励；默认一级 +1、二级 +3、三级 +2，实际应读取当次生效策略。
- 维科夫结构分已进入量化综合分，不能在新闻融合时再加一次。独立维科夫 100 分模式与扫描器结构分口径不同，不能混用。
- 报告已有新闻证据独立章节，但未形成每只股票可复算的统一明细。当前计算使用全部合格新闻，输出只保留前 8 条、报告再取前 2 条，不能完整解释总分。

## P0：先建立准确的评分账本

1. 评分函数在计算时产生结构化明细，渲染层只展示，不根据文案推测分数。覆盖扫描器普通与批量评分路径。
2. 每条明细记录：标的、类别、规则编号和版本、输入值、调整前后值、原始分、权重、实际贡献、证据编号、数据提供方、数据日期、获取时间、质量状态、是否影响正式分。
3. 来源分成两层：数据来源（公告链接、行情接口、数据日期）和判分来源（策略规则、阈值、版本）。维科夫必须链接到事件日期、确认日期、价格/成交量证据和阶段规则；数值奖励注明“策略设定”，不能说成公告结论或维科夫理论规定。
4. 计算链展示为：维度加权贡献 → 原始综合分 → 覆盖率调整 → 新鲜度调整 → 质量分 → 维科夫买点奖励 → 正式优先分 → 新闻影子调整 → 新闻影子优先分。封顶与四舍五入单独记录，保证复算一致。
5. 维度内部如果有中性基准和加减项，展示真实基准及各项；权重贡献不伪装成独立加分。阶段查表结果不虚构为多条事件累加。
6. 硬门槛单列通过/等待/拒绝及证据，不能折算成可被新闻利好抵消的扣分。

交付：统一账本契约、评分路径接入、维科夫证据映射及复算测试。

## P1：新闻证据可靠性与逐项加减分

1. 保留公告优先，新闻作为补充。每条证据保存原始标题/摘要、原文链接、发布主体、发布时间精度、首次获取时间、关联股票和事件编号。
2. 区分行情依据日与本次决策时间。盘后/周末新消息可用于新的决策时间，但不得回填上一交易日历史推荐。只有日期而没有具体时间的当日证据采取保守处理，不能默认零点而提前使用。
3. 官方来源校验使用解析后的可信域名及数据提供方契约，不能仅凭来源文字或 URL 子串。正式重大风险与媒体风险提示分开；现代码媒体 critical 也会触发影子否决，与“正式风险”设计口径需统一。
4. 同一事件转载、公告更新和重复标题合并，避免反复加减；业绩事实同时进入基本面和新闻时标记重复，并明确唯一计分归属。行业政策仅在相关性有证据时归到个股。
5. 标题关键词仅作为线索；完善否定语境、减持完成、解除质押、拟议事项、问询与处罚区别。无法确认时标记待核实；无新闻、部分源失败、全部源失败分开，不把缺数据表述为中性事实。
6. 每条新闻展示：基础分 × 来源系数 × 时间系数 = 贡献；随后展示去重、去重计分、封顶或重大风险覆盖的实际变化。完整冻结所有计分证据，页面可折叠，不因显示条数限制丢失账本。
7. 首版沿用 [-3,+1] 影子范围，全部新权重或分类变化记录规则版本。正向新闻不能越过市场、数据、板块、资金和维科夫门槛。

交付：可回放新闻证据、新闻明细账本、明确的新旧决策时间契约。

## P2：同一候选卡并排展示

主表保留推荐资格、正式优先分，增加新闻净调整、新闻影子优先分和重大风险状态。每只股票展开后按以下顺序展示：

| 类别 | 内容 | 来源展示 |
|---|---|---|
| 常规量化 | 动量、量价、资金、基本面、板块的基准及加减项 | 数据提供方、日期、规则版本 |
| 维科夫 | 阶段结构贡献、严格买点奖励、未确认或失效原因 | K 线日期、事件/确认日、规则编号 |
| 新闻 | 利多、利空、混合、待核实及逐项分值 | 公告/媒体名称、发布时间、原文链接 |
| 汇总 | 正式分计算式、新闻影子分计算式、资格结论 | 全部证据可展开核对 |

示意（虚构数值，仅说明排版）：原始分 70.0 → 覆盖率 0.90，调整 -7.0 → 新鲜度 1.00，调整 0 → 质量分 63.0 → 严格二级买点 +3.0 → 正式优先分 66.0 → 新闻净影响 -1.2 → 新闻影子优先分 64.8。结构分已包含在 70.0 中，不再累加。

HTML、Markdown、JSON 共用账本，避免三种格式结论不同。报告正文使用易懂标签，规则路径放在展开的溯源详情。保留今日可执行、等待触发、观察池的区分。

交付：统一候选明细、计算式、可点击证据及折叠说明。

## P3：验证与启用条件

- 先验证不改变现有正式分、排名和资格；账本每一项均可追溯，计算误差仅限明确的舍入规则。
- 新闻测试覆盖未来时间、日期精度、周末消息、转载去重、来源伪装、否定语境、部分/全部源失败、超过 8 条证据及封顶/否决。
- 维科夫测试覆盖结构分不重复、策略覆盖默认奖励、未确认买点不获奖励、失败突破不能由新闻放行；普通与批量扫描结果一致。
- 验证历史快照缺少新字段时仍可读取，新快照保存账本及全部计分证据，历史回放不使用当时不可知的信息。
- 修改脚本后必须运行：`python3 .claude/skills/stock-trend/tests/test_stock_trend.py` 和 `python3 .claude/skills/stock-trend/tests/test_golden.py --diff`，使用实际可用的 Python >=3.10。只有确认预期变化后才更新黄金快照。
- 使用固定输入生成示例报告验收，再联网跑一次统一今日推荐，检查数据降级与后台快照状态。此前报告出现的 membership_data_date 时间校验失败若仍存在，先查明时间语义并修复，不能跳过校验写入研究样本。
- 冻结同一候选宇宙下正式策略与新闻策略结果，跟踪 5/10/20 交易日收益、超额收益、胜率、MAE、覆盖率和风险误报；补充 60/120 日以匹配 1–6 个月使用场景。
- 样本门槛、成本和启用判据在验证前预先固定，分市场环境检验。证据不足继续影子观察；正式启用单独发布，支持退回影子模式。

## 实施顺序与完成定义

按 P0 → P1 → P2 → P3 推进。先用固定证据打通一只股票，再覆盖全候选；不先调整新闻权重来追求更好排名。

报告融合完成的标准：用户能在同一候选详情看到三类加减法，点到原始来源，并复算正式分和新闻影子分；任何缺失、未确认或影子结论均有明确标识。新闻正式参与选股属于后续验证阶段，不与展示完成混为一谈。

本报告仅供学习参考，不构成任何投资建议。股市有风险，投资需谨慎。
