# 今日推荐 AI 自进化实施计划

日期：2026-09-07。状态：P0–P4 已实施；本文件不表示策略有效性已验证。

## 目标与范围

建立“正式记录 → 到期评价 → 分组诊断 → AI 实验提案 → 时间外验证 → 影子运行 → 版本发布”的可复现闭环。第一版优化候选筛选与同层排序，保持今日可执行、等待触发、观察池的产品定位。

第一版不自动交易，不在线自改代码，不自动放宽市场环境、数据质量和板块证据硬门控；候选报告继续不展示或依赖交易计划。交易收益评价独立存在，不作为候选研究的必要条件。修改这些边界应另行设计和验证。

## 已核实的基础与待核查问题

- `core/recommendation_snapshot.py`：正式快照、内容摘要、冲突留痕，可复用；旧正式记录不得覆盖。
- `analysis/recommendation_attribution.py`：已有 5/10/20/60 日信号评价、交易评价、基准比较和独立归因文件。
- 当前成熟观测跨窗口相加，不等于独立样本；当前 calibration_readiness 同时要求信号和交易成熟，需拆分研究资格。
- CostModel 默认零成本；交易研究必须显式选择并记录成本情景，零成本仅标记毛收益。
- 已有市场风格影子观察；复用隔离思路，新建候选策略实验契约，不直接修改原风格模型协议。
- 实施前核查 default_series_loader 的证券代码解析、历史获取范围是否覆盖评价日、复权一致性和长窗口历史长度；代码审阅中的疑点须用测试确认，不能直接认定为故障。
- 未检查历史报告或缓存样本，不能假设现有样本量足够。

## 评价契约（P0 首先冻结）

1. 主指标：20 个交易日候选信号相对沪深300的平均超额收益；沿用现有次一交易日收盘起算口径并显式记录。60 日为中线确认，5/10 日仅诊断；任何窗口端点以固定交易日样例测试锁定。
2. 辅助指标：中位数超额收益、相对板块收益、个股窗口 MAE/MFE、每日推荐数量、空推荐比例、行业集中度、数据可评价覆盖率。个股 MAE 不称为组合最大回撤。
3. 研究范围：实际扫描宇宙；不声称覆盖全市场。观察池和淘汰对象均可用于事后比较，但缺行情不能记为零收益；硬过滤的非目标证券不纳入可投资对照组。
4. 每个日期等权汇总后比较新旧策略，避免推荐数量多的日期占据过大权重。任一策略无推荐的日期单列覆盖与空缺；共同有推荐日期做配对比较，全日期应用效果须另用明确的资金与现金规则模拟。
5. 每个窗口单独统计：正式日期数、成熟日期数、股票数、原始记录数、去重信号数。主窗口同一股票 20 个交易日内重复信号合并为一个研究事件；保留原始记录供审计。去重后也不假定样本独立，统计不确定性按时间块处理。
6. 缺失、未到期、停牌、不可成交、有效样本分别计数；候选信号涨幅不等于可成交收益。交易评价另处理成交、费用和滑点。
7. 初始研究门槛：主窗口至少 20 个成熟推荐日期、100 个去重成熟事件；这是启动研究的工程门槛，不是统计显著性保证。分组不足 30 个事件仅描述，不生成该组调参提案。上述数值在第一次实验前冻结。

## 实施阶段

### P0：修正评价基础（已完成）

涉及：`analysis/recommendation_attribution.py`、现有 attribution/lifecycle 测试；新增 `core/evolution_contract.py`。

- 定义版本化评价契约，拆分 candidate_research_readiness 与 trade_research_readiness，兼容原输出字段。
- 按主窗口重算成熟度，增加去重计数、缺失率、日期覆盖；没有交易计划不能阻塞候选信号研究。
- 用真实接口契约和离线夹具核查加载器疑点；如有缺陷则修复。决策输入严格截至推荐日，结果数据可延伸至评价日，两者独立保存。
- 评价版本、成本、复权或基准口径改变时写入新版本目录，不合并不同口径的历史评价。

验收：同一推荐的四个窗口不能计成四个独立事件；未到期结果保持 pending；行情失败可重试；同输入结果可复现；旧快照可读取且摘要不变；无交易计划仍可评价候选。

完成记录（2026-09-07）：新增版本化评价契约，默认主窗口固定为 20 日；主窗口同代码的重叠持有区间去重，成熟度、日期覆盖和可评价覆盖按主窗口重算。候选信号研究与交易模拟研究分别给出就绪度；无交易计划不再阻塞候选研究。评价契约的成本、复权、基准或窗口变更会使用独立的 `contract_id` 目录，避免合并不同口径的 sidecar。交易评价补充主窗口事件端点；加载器以评价截止日校验结果行情覆盖，避免只验证推荐日。短窗口命令仍可用于诊断，但不产生研究就绪结论。

### P1：保存可研究样本（已实施）

涉及：`scans/daily_candidates.py`、必要的 `scans/stock_scanner.py` 接口；新增 `core/candidate_research_snapshot.py`。

- 在截断 Top N 前记录扫描对象、阶段、入选/淘汰原因、分项分数、质量调整分、买点奖励、市场环境、板块持续性和数据证据。
- 每条附 run_id、代码、依据日、known_at、来源日期、原始数据引用/摘要、策略与参数摘要；模型/提示词仅在参与判断时记录。
- 研究记录独立保存并关联正式快照；盘中标临时，不进入正式训练集。同日冲突运行留痕，不当成额外独立样本。
- 历史缺少的淘汰原因或扫描宇宙标记 unknown；从上线日向前积累，禁止拿今天成分回填当时宇宙。

验收：每个已扫描对象有终态或明确失败状态；截断淘汰可追溯；研究写入失败不影响原推荐输出；重复运行幂等；新记录不改变原排名和资格。

### P2：统计归因与 AI 提案（已实施）

新增：`analysis/recommendation_diagnostics.py`、`analysis/evolution_proposals.py`、提案 JSON schema 与提示词资源。

- 按分桶、买点等级、市场档位、板块持续性和质量分做单维诊断；第一版不搜索大量交叉分组。
- 输出各组样本量、主指标、MAE、缺失情况和时间分布。归因只表示相关，不能声称因果。
- AI 每周最多生成 3 条假设；每条必须包含证据记录引用、反例、单一修改变量、预期方向、失败条件和冻结的验证方案。
- Python 计算所有指标并校验 AI 引用；AI 无法引用有效证据或样本不足时，输出“继续积累”，禁止编造提案或直接改参数。
- AI 调用通过可替换适配器；默认可离线产生研究材料并由当前 Agent生成提案，自动任务需配置可用模型和凭据，模型不可用时仍完成统计。首版限制每周一次生成和一次格式修复，并记录用量。

验收：无成熟样本不出调参结论；错误引用或越界参数被拒绝；同一统计包不重复创建提案；模型失败不阻断数据评价。

完成记录（2026-09-07）：新增固定的单维诊断包，按最终分桶、买点等级、市场环境档位、板块持续性和质量分档输出样本量、主指标、窗口 MAE、缺失状态及成熟日期分布；诊断明确仅表示相关。提案模块提供可替换模型适配器所需的 JSON schema 和离线研究材料；不配置模型时仍写出“继续积累”或无有效提案状态。提案最多三条，逐条校验证据引用、每组至少 30 个成熟事件、单变量边界（仅同层排序的买点奖励，0–3）以及反例、失败条件和冻结验证方案；不合格提案不会影响任何参数或推荐输出。

### P3：滚动验证与影子比较（已实施）

新增：`backtesting/recommendation_experiments.py`、`core/evolution_registry.py`；在候选入口接入可选影子配置。

- 先支持一个实验：严格买点奖励 `+1/+3/+2` 对照 `0/0/0`，只改变同层排序。资格、扫描宇宙、Top N 和其他条件固定。
- 用历史完整研究记录重放；若某项实验需要未保存的输入，拒绝该实验，不用当前数据代替。扩大扫描宇宙的实验需先补采数据。
- 按时间划分训练、验证和最终保留集；标签窗口跨越分界的样本剔除，隔离长度按该实验最大评价窗口确定。没有足够时间跨度就等待，不能随机拆分替代。
- 登记所有尝试，包括失败和零提升；固定时间块 bootstrap 方法、随机种子与区间口径。每轮最多 3 个候选实验，最终保留集仅在方案冻结后使用；看过后不得继续当作未见数据。
- 影子版本使用相同日期和输入独立输出，保存差异原因与配对结果，不写正式推荐历史、不参与展示中的正式推荐。

初始晋级标准（实验开始前冻结）：主窗口去重成熟事件 ≥100、成熟推荐日期 ≥20；至少 3 个有效样本外时间段；新旧日期配对超额收益差的 95% 时间块置信区间下界 >0；推荐覆盖率不低于基线的 90%；MAE 尾部不利幅度不比基线恶化超过 1 个百分点；60 日成熟样本不足时仅保留影子资格。各门槛为首版工程约定，不能承诺收益。

验收：未来数据注入和重叠标签被检出；相同输入重放一致；无差异实验正确报告零变化；任一资格硬门控不可被实验越过；证据不足无法晋级。

完成记录（2026-09-07）：新增冻结的买点奖励对照实验（`+1/+3/+2` 对 `0/0/0`），回放只对已保存且仍通过原有资格门控的候选做同层排序；缺少完整候选或 Top N 输入会拒绝该日期，绝不以当前数据回填。时间外验证固定为三段有序样本外区间，相邻区间留出 20 个交易日标签隔离；不足跨度即输出“继续积累”。比较按推荐日期配对，固定日期块 bootstrap、随机种子和区间口径；零差异明确保留。新增不可变实验登记及受限状态迁移，结果写入独立 experiments 目录，不影响正式推荐。影子运行和晋级仍须满足计划中冻结的事件、日期、覆盖和 MAE 尾部条件，当前实现不会自动发布或切换正式策略。

### P4：运行与发布管理（已实施）

新增：`analysis/evolution_job.py`；扩展实验注册表与运行文档。

- 收盘流程：先完成正式上下文、板块快照和候选记录，再运行到期归因。非交易日不伪造新推荐；上游失败保留缺口，下次重试。
- 每周：生成诊断材料与提案；实验任务只消费已登记的冻结方案。命令支持 --dry-run、--as-of 和幂等重试。
- 注册表状态：draft → validated → shadow → eligible → active → retired/reverted；状态迁移附证据摘要，正式发布首版采用显式发布命令，不由 AI 提案直接触发。
- 版本指针切换原子化，保留前一版本；快照记录实际使用版本。监测数据失败率、推荐覆盖和成熟收益，预注册退化阈值；统计退化先标记复核，接口/契约故障停用实验版本并恢复已验证版本。
- 调度安装按实际部署环境落实，不默认打开浏览器；日志与研究材料默认写 cache 子目录，生成面向用户的报告另走报告命令。

验收：中断重跑不重复写入；任务失败有阶段与原因；新版本可回滚；回滚不改旧记录；不配置模型也能完成采集和统计。

完成记录（2026-09-07）：新增 `evolution_job.py`，提供 `close`、`weekly`、`monitor`、`publish` 和 `rollback` 子命令，以及 `--dry-run`、`--as-of`。收盘任务只消费已存在的正式快照；缺失/无效上游记录明确留为 gap，不伪造推荐。周任务离线完成诊断和无模型提案，实验只能按已登记的冻结定义回放。注册表保留不可变登记文件，状态迁移以带证据的追加事件保存；发布要求显式 `publish`，并原子切换版本指针，候选快照记录实际 `evolution_version`。损坏或缺失的指针回退原始基线。监控保留预注册的数据失败率、推荐覆盖和成熟 alpha 阈值，统计退化仅标记复核。回滚只移动当前版本指针，不修改既有正式推荐记录。

## 存储与兼容

新增数据统一放 `.cache/stock-trend/evolution/` 下的 research、evaluations、diagnostics、proposals、experiments、shadow、registry 子目录。所有派生材料关联输入摘要与版本，schema 升级提供旧记录读取路径。正式 recommendation_history 保持原位置和不可变语义。

研究原始输入应有可复现引用或归档，不能仅依赖会过期的行情缓存；不保存模型凭据。旧历史只能支持其实际字段允许的研究。

## 质量门禁与交付顺序

每阶段独立提交。改 scripts 下 Python 前说明影响范围，改后都执行：

```bash
python3 .claude/skills/stock-trend/tests/test_stock_trend.py
python3 .claude/skills/stock-trend/tests/test_golden.py --diff
```

新增契约、去重、时间隔离、AI 引用校验、重放和版本回滚的针对性测试，并接入主测试入口。不得为消除失败盲目更新 golden；预期输出变化逐项确认并在提交中说明。

第一批交付仅 P0+P1：得到可信且持续积累的数据闭环。第二批 P2：输出有证据的研究提案。第三批 P3+P4：完成验证、影子和发布管理。工程估计合计 13–19 个工作日，不含外部数据故障与模型配置等待；样本外评价按交易日自然成熟，不能承诺工程结束即可晋级。若无可用历史，60 日确认至少要等待相应交易窗口，更长的滚动验证还需额外时间。

完成定义：闭环可运行且所有质量门禁通过；数据不足时正确停止在“继续积累”。策略晋级是独立结果，允许没有任何实验胜出。

本计划仅供学习参考，不构成投资建议。
