# 每日复盘工作流

## /daily-review [--no-refresh] [--json] [--no-html]

今日复盘 + 市场环境评分 — 整合全市场上下文(大盘/成交额/涨跌家数/涨停/资金/板块排行),输出 0-100 市场环境评分 + 每日复盘报告,并持久化 `market_regime.json` 上下文供 `/stock-trend` 做大盘/板块对比。

**评分公式**: 大盘趋势(25%) + 成交额(20%) + 赚钱效应(25%) + 涨停情绪(20%) + 资金(10%)。≥80 强势(可建仓)/ 60-79 中性(轻仓观察) / <60 弱势(降仓/空仓,不找牛股)。

**评分解释与数据资格**: 正式大盘趋势组件当前使用上证(`000001.SH`)、沪深300(`000300.SH`)和深成指(`399001.SZ`)的 MA20 状态平均；中证500、 中证1000、创业板指和科创50不自动计入该正式分，除非后续版本明确变更模型。成交额组件另用上证与深证综指(`399106.SZ`)拼接两市成交额。每次上下文同时保存 `market_explanation/v1`：五项分数、权重、归一化分母、贡献、指数名单及证据资格。`data_quality=partial` 是正式推荐硬门控，不能因为分数可计算就放行。

证据资格与分数状态分开记录：完整/部分/缺失、fresh/stale/unknown、primary/alternative/estimate/unknown、scorable/reference_only/unavailable。市场资金正式使用全市场主力净流入(`market_main_force_net_inflow`)；该数据有效时标记 `primary`/`scorable`，不因北向数据不可用产生 `partial` 或 `regime_data_partial`。其他组件仍按各自完整性标记，缺少来源时间戳不得标记为 fresh。盘中解释额外保存锚分、外推分和混合权重；无法取得锚证据时只显示已存正式分，不声称组件合计解释了盘中混合分。

**日期证据与结论资格**：`data_date` 仅保存可核验的来源交易日，缺失保留 null；`requested_date` 是请求日，`fetched_at` 是本机采集时刻。`date_origin=provider/request/unknown` 与 `alignment=matched/mismatched/unknown` 分开记录。逐只核验三个趋势指数的末条有效收盘日期；赚钱效应同时核验涨跌家数和行业排行日期。假期采集或无来源日期的快照不自动对齐报告日。

上下文与解释保存独立 `conclusion_qualification`。组件完整且来源交易日全部匹配才可支撑结论；没有来源事件时刻时显示“交易日已核验，事件时刻未知”，时效仍为 unknown。证据不足时 HTML/Markdown 显示“参考评分（模型计算分）”及“证据不足，以下为模型提示”，保留原分数、公式与模型质量。推荐入口统一投影有效质量：原 good 且资格不足降为 partial，原 partial/missing 保留；旧缓存重新核验证据，不自动放行。未核验记录可冻结供参考，不可充当合格收盘对比基线。

新增 `detail_inputs` 冻结收盘价、MA20、真实成交均额与样本数、涨跌家数和行业计数、涨停/连板/最高板及基线、主力净流入与覆盖范围。详情只读冻结字段，未保存值不倒算、不联网补齐历史。

**盘中混合口径**: 交易时间内跑，评分为「上一收盘锚 + 盘中按已过 240 交易分钟占比外推」的混合 —— 半日成交额/涨停/涨跌家数按已过时间占比放大估全天值再打分，早盘(开盘约 40 分钟内)不外推、直接用上一收盘。越早越依赖昨收，因此**不会因半日数据误报弱势**。报告标 `盘中临时`，输出含 `intraday: true` + `intraday_note`；盘中快照**不写** `market_regime_history.json`(避免 partial 数据污染后续基线)。

**步骤**：

1. 运行(默认生成 HTML,`--no-html` 仅 MD,`--json` stdout 结构化输出):
```bash
python3 .claude/skills/stock-trend/scripts/analysis/market_regime.py [--no-refresh]
```
2. **默认打开 HTML 报告**:
```bash
open -a "Google Chrome" reports/lists/daily-review-<最新时间>.html
```
3. 数据源: 指数K线(东财→BaoStock降级)、行业板块排行、涨停池(AKShare)、地域板块涨跌家数/全市场主力净流入。
4. 输出: 复盘报告(①市场环境 ②板块最强/最弱) → `reports/lists/daily-review-<时间>.md` + `.html`；HTML 另含 ③“观察列表”。该区块唯一标的来源是 `observation_list.yaml`，按同一依据日对 YAML 中每只股票执行今日推荐的六维分析（动量、量价、资金、基本面、板块强度、维科夫），展示六维分数、综合/质量分和数据诊断；不读取候选扫描的 `buckets.observation`，不展示候选新闻影子分或推荐数量门槛。统一入口先呈现“YAML 观察列表六维分析进行中”，分析完成后后台原子替换同一报告链接；失败只降级该区块，不阻断市场评分或正式推荐。分析 artifact 必须绑定依据日和 YAML 内容摘要，历史重放不得使用未来 K 线。
5. 持久化: `market_regime.json`(今日上下文,供 /stock-trend 对比)、`market_regime_history.json`(30天,支撑涨停/成交额均值)。`--no-refresh` 仅重用市场缓存并直接读取观察列表，不写回观察列表配置。

### 与上一交易日比较

HTML、Markdown 与 JSON 共用 `review-comparison/v1` 结果。用冻结的权威日历按报告依据日确定紧邻上一交易日；休市重跑仍比较同一对交易日，缺失相邻日不跳到更早样本。盘中仅列“上一收盘参考”，不输出混合分对收盘分的改善或恶化结论。

新增摘要位于 `.cache/stock-trend/review_snapshots/<依据日>/<内容摘要>.json`，绑定源上下文摘要与实际冻结时间，保存模型/口径版本、正式或盘中状态、指标范围、权重和分母；只对满足15:10完成确认及完整日期资格的收盘记录原子更新合格指针。重放只取截止前已冻结的记录，最新指针晚于截止时可读取此前合格的不可变摘要。旧 history 保持只读兼容，不批量迁移、不为比较字段覆盖同日历史。旧数据缺版本不可比较分数；缺可核验冻结时刻不能作为历史基线。

总分与五项分差仅在两日版本、指标覆盖、权重/分母、收盘口径及证据资格一致时展示。原始成交额在日期和沪深覆盖均合格时单独显示金额及百分比变化。主要变化按同权重模型贡献差的绝对值排序，仅解释模型内贡献，不推断市场涨跌的因果。未舍入模型分差与显示总分差分别记录，显示舍入残差不归为某项贡献。无网或证据不足时明确展示不可比原因；比较失败不阻断主复盘，也不参与评分。`--no-refresh` 仅读本地冻结日历与历史摘要，不生成新的冻结摘要。

### 五项评分详情

市场环境摘要表的五行各有一个“查看详情”链接，跳到同一报告中的对应说明。详情保留本报告分数、说明、依据日与来源时间资格，介绍评分口径，并提供东方财富指数、沪深京A股行情、行业板块、涨停池、大盘资金流和同花顺两市成交总额页面入口。外链在新标签页打开；这些网页可能显示最新行情或历史缓存，须核对站内日期，不能作为本报告依据日数值的自动核验。跨渠道覆盖范围与资金算法可能不同，本报告评分仍以冻结证据为准。

详情渲染不联网、不重算评分；旧缓存没有保存的收盘价、MA20、20日成交均额或个股名单显示未保存，不通过四舍五入后的说明倒算。

### 首页与手机阅读

首页依次展示依据日与报告状态、正式或参考评分、主要变化、五项简表、板块、美股和观察列表。五项详情与评分解释位于正文末尾，HTML 使用原生 `details/summary`；技术字段和原始资格证据放在展开内容里，评分及日期口径不变。

“查看详情”、直接访问详情 hash、浏览器前进后退会展开对应内容并滚动；禁用 JavaScript 后仍可手动展开。手机宽表在各自容器内横向滚动，长证据字符串可换行。Markdown 保留完整正文、五项详情和阅读目录，不依赖折叠交互。HTML 与 Markdown 初次生成共用观察列表状态；`--no-html` 同样生成观察列表，`--no-refresh` 只读取已有分析。后台观察列表更新同步替换 HTML 与 Markdown；共享同一冻结 state 和报告锁，各文件原子写入，部分失败会返回文件级状态，幂等重跑可恢复。

历史详情补充器兼容旧布局与新折叠布局，只调整表现并保留原注释、冻结评分和其他区块；报告路径锁、原子写入和重复执行幂等规则继续生效。阶段4验证只使用临时目录中的本地 fixture，不自动修改已有报告。

### 美股区间概要

每日复盘另在板块与观察列表之间展示独立的美股区间概要，Markdown 同步展示。不影响 A 股评分或评分历史。运行先采集并冻结权威A股日历，再冻结一次带时区 `as_of`。独立 `a_share_anchor_date` 是截止时刻最近已确认完成的A股交易日；当天15:10前不算已完成，锚点实际时刻仍是该交易日北京时间15:00。早晨、盘中或假期不改变A股报告 `basis_date/data_date`。以锚点之前最近美股收盘作基准，统计到截止时刻已完成的美股常规交易日。未收盘、盘前、盘后报价不计入。

权威日历证据冻结在 `.cache/stock-trend/review_time/<内容摘要>.json`，保存交易日列表、覆盖、来源、实际采集时间、15:10确认阈值及15:00锚点口径；报告绑定证据摘要，并保存锚点候选的完成判定。选择时拒绝晚于截止的证据，且需要日历覆盖截止日。覆盖不足时只接受已核验、在截止前冻结的完整日K线作为降级锚点，明确不能确认是否为最近交易日；无证据时锚点显示未核验，不猜节假日。历史截止运行不能用后来采集的日历证据冒充当时已有记录。

累计区间与最近已完成美股交易日分开显示。即使区间没有新增收盘，仍可用该美股日及前一交易日的复权收盘计算单日涨跌，明确“区间无新增交易日”；区间收益保持为空。美股已收盘但提供方尚未返回终点时，最近日涨跌保持缺失，不用较早报价替代。美股年度日历覆盖不足、缺少端点、可选 yfinance 依赖缺失或请求超时，均只降级该区块；现有25秒行情超时预算不变。

展示4个大盘ETF代理、11个标普500行业ETF代理和版本化固定个股观察池，包含区间复权涨跌、最近一日涨跌及相对SPY的百分点差；代表池不是全市场涨跌榜。来源、实际交易日和降级状态均在报告中注明。新缓存使用 `us-market-summary/v2`，身份含报告依据日、独立锚点日、时间口径版本、锚点证据摘要、最近美股日、区间终点、配置及日历版本。`--no-refresh` 先仅读本地冻结锚点证据，再定位完全匹配的美股缓存，不调用日历联网加载器；拒绝截止或冻结时间晚于请求时刻的缓存，不按新口径解释旧v1。没有匹配缓存时明确降级，不联网补齐。

### 板块持续性与观察列表变化

板块排序仍表示当日排名。仅对展示的最强10、最弱3和已有观察标的的可核验关联板块去重取数，最多4路并发、12秒总预算，显式请求80条收盘记录。5/20交易日收益分别要求权威日历对应的末6/21个连续端点，板块ID、分类版本、来源和前复权价格类型一致；不累计每日百分比，不建立全市场中期收益排名。连续上涨按收盘价逐日比较，有限记录未找到起点时显示“≥N”；没有完整上涨/下跌/平盘家数与覆盖范围时，上涨比例显示缺失。盘中未完成或日历未核验时不展示未确认收盘收益。

板块证据冻结在 `sector_persistence/<依据日>/<运行摘要>.json`，保留实际采集时刻、依据日、运行截止、日历来源/摘要、板块身份和收盘记录。市场上下文只绑定本次选定对象与artifact路径；`--no-refresh`严格读取这次冻结记录，不读取当前YAML决定板块、不查找不明日期最新K线、不联网。早期上下文没有运行绑定时明确缺失。观察关联板块身份或artifact未齐备时单独说明覆盖缺口；不扩大为全市场成分抓取。

观察artifact为 `yaml-observation-analysis/v2`，冻结规范化行配置、市场+代码、加入日期、评分模型版本、配置摘要、质量方法/签名及证据截止日。当前artifact继续校验当前YAML；历史加载仅校验历史自身冻结配置。质量签名保留来源、覆盖、资格和方法输入，排除随交易日变化的采集/请求日期；各行日期另行核验，未来证据与未来冻结拒绝使用。

只比较权威日历紧邻且已确认完成的两次交易日记录。缺相邻日不以较早记录冒充昨日；v1仅支持“记录集合”新增/移除，不能断言为YAML操作，也不能比分数/结构。v2分别列出YAML新增/移除和结构事件，优先显示结构失效、结构恢复、数据恢复及已有确认事件。模型/配置变化或代码重入禁用纵向比较；质量/数值方法不同禁用分差，已核验的结构事件独立展示，状态未知不能推断有效或新增买点。此辅助证据不参与市场评分或正式推荐资格。

统一入口的 `--json --html` 也会生成匹配Markdown。后台pending/ready/degraded共用状态同步两份报告；分析失败清除pending并说明原因，任务标为partial；文件级失败在状态中可定位，重跑修复。跨文件更新不是事务，不能将一个文件成功解释为两份均成功。
