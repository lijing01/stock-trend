# 弱转强主表 Top 30 计划

日期：2026-10-28。范围：报告观察优先级与展示，不修改正式推荐资格。只规划，不实施。

## 现状证据

- 用户指定 HTML 的旧版弱转强表有 67 行：10 行缩量待突破、45 行结构有效回调、12 行无当日信号；没有收盘确认信号。第一行虽有当日形态，但跟踪待复评。
- reporting/weak_to_strong.py:304 的 `_merged_rows` 合并当日与跟踪记录，失效和待复评优先；:390 起渲染全部记录。不能直接截前30。
- scans/daily_candidates.py:5222 起基于研究池独立计算弱转强，与正式候选 top 参数不同。
- 工作区已有未提交的 v2 展示修改。reporting/weak_to_strong.py:500 的排序已有数据资格、均线方向、偏离风险及背景质量，:574 起按阶段渲染，但未限额。实施前保留并兼容这些修改。

## 方案

1. 定义一个共享的主表选择结果，供 MD/HTML/JSON 展示消费；原始形态与跟踪数据完整保留。默认全模块最多30只证券，不是每组30只，不与正式候选 top 混用。相同证券跨周期只展示一行；选当日有效且优先级最高记录，其余周期留诊断。按证券和周期严谨关联，不能把旧周期状态套到新周期。
2. 主表资格：当前依据日数据合格、收盘证据完整、结构未失效且周期状态无未解决冲突。失效、待复评、过期、缺数据、盘中临时记录移到折叠诊断，不占30个名额；不通过正式推荐门仍可展示为观察，明确限制，不自动升为可执行。保留风险提示，主表不足30不凑数。
3. 排序先比较阶段：v1 收盘确认/有效增强 → 缩量待突破/有效延续 → 结构有效回调；v2 区间突破 → 局部转强 → 早期修复 → 准备观察。v1/v2分别使用自身语义，不合并成无依据的统一得分。
4. 同阶段沿用已有质量字段并调整优先次序：若字段可得，先比较均线方向（MA10和MA20上行、MA20上行、其他、未知），再比较风险（无偏离/跌回触发位等风险者优先）；按各背景自身质量比较。确认类先收盘强度，再量能达标程度、偏离；准备类先缩量质量，再回撤与调整天数；v2沿用背景专用比较。突破量比不按无限增大加分；量能上限/偏离阈值只复用已有检测合同，没有合同则保留现有量比次序并标注局限，另行研究后才引入新阈值。缺失指标最后，不能默认填0或当作低风险；跨背景不直接比较 Va/V0。v1没有均线字段时跳过该维度并披露。
5. 板块持续性只在同阶段、同质量档且双方证据完整时作为次级比较；概念标签数量不加分。资金/新闻/基本面证据可能仅覆盖正式候选，首版不纳入全池排序，缺失不得当作无风险。最后按代码及周期稳定打破并列。
6. 对过滤、去重后的全池统一排序后截取30，再按阶段展示。新增名次、入选原因、主要限制；顶部给出扫描数、有效证券数、展示数、未展示数与排除原因。诊断折叠保存旧信号和失败项；正式推荐状态继续独立显示。首版不增加交易计划字段、行业强制配额或未经验证的100分投资分。

- 运行弱转强专项测试，以及项目要求的 test_stock_trend.py 和 test_golden.py --diff；不为了通过而更新golden。
