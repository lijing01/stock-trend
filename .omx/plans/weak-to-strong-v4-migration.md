# 弱转强 V4 迁移与展示计划

## 目标与范围

以 `../stock-kline` 的 V4 替换当前弱转强的默认计算和展示，并使结果可追溯、可验证、可回滚。先接入影子模式，再根据量化验收结果切换；本计划不实施代码变更。V4 目前标记为研究用途，历史规则未通过且前向验证未完成，迁移正确不等于策略有效。

当前链路：`scripts/scans/stock_scanner.py:2800` 调用 V1；`scripts/scans/daily_candidates.py:5231` 组装 V1，并在 `:5796` 生成 V2、跟踪和快照；`scripts/reporting/weak_to_strong.py:582`、`:846` 分别负责 V1/V2 展示。以上路径均位于 `.claude/skills/stock-trend/`。

源算法入口为 `../stock-kline/src/kline_lab/research/v4_algorithm.py:104`；批量入口和市场分类分别为 `src/kline_lab/strategies/v4/scan.py:13` 和 `market.py:83`。V4 组合 V1/V3 检测与 T1/T2 模型，仅接收当日新确认且符合条件的事件，不等价覆盖旧版 watching、pullback、provisional 状态。

## 实施步骤

1. **固定基线与数据合同。** 记录两仓提交、源算法和模型 bundle 指纹，梳理 V1/V3、特征、模型和运行依赖。建立固定输入样本，记录事件、特征、预测及排序；明确复权方式、OHLCV 单位、证券代码、交易日历、停牌和收盘确认数据的对应关系。将样本及容差写入测试，不能用现有 V1/V2 结果冒充 V3 事件。
2. **引入完整算法和模型管理。** 将必要 V1/V3/V4 依赖及适配层纳入当前工程，运行时不依赖相邻仓库路径；复用扫描已有行情和收盘证据。导入或可复现生成月度 T1/T2 bundle，校验 schema、哈希、训练截止、验证起始、有效期及样本条件。模型缺失、无效或过期时返回明确原因，禁止用旧分数冒充 V4 分数；确认后续月份的模型产出及部署责任。
3. **并行接入扫描。** 在 `scripts/scans/daily_candidates.py` 接入 V4 批量分析和市场汇总，新增独立 `weak_to_strong_v4` 合同：as-of 日期、覆盖范围、事件/周期 ID、T1/T2、状态及原因、模型版本、特征快照或哈希、预测。保留旧链路和原排序作为对照；非当日、证据不足、非 T1/T2 均按源算法明确处理。T1/T2 各自按预期净收益、胜率排序，fallback 不进入有效排名。
4. **调整展示与持久化。** 更新 `scripts/reporting/weak_to_strong.py`、报告 JSON/HTML/Markdown、`scripts/core/weak_to_strong_snapshot.py` 及 follow-up 消费方：展示 T1/T2 分组、预测值、状态、模型版本、数据覆盖和原因，影子期标识研究用途；另列结构观察、无新信号、数据不足，不能将缺失数据解释为没有机会。旧观察状态暂在独立旧版观察区展示，明确其来源，禁止映射成 V4 信号。快照和跟踪按版本隔离，不跨版本解释事件。
5. **验证与影子运行。** 用固定输入跨仓比较事件 ID、特征值/哈希、类型、模型版本、预测、排序和回退原因；浮点容差实施前固定，差异逐项解释。对完整每日链路历史回放并记录覆盖、差异、错误和回退率；之后累计至少 20 个不重叠的前向五交易日块并与冻结基线比较。核查历史证券名册、日历、复权、停牌、涨跌停和成交约束；已查看的历史不计入前向样本。
6. **验收后切换。** 冻结并记录源研究规定的历史及前向量化门槛与成交口径，确认其通过后，通过显式版本配置让 V4 接管默认展示和选择；保留旧实现、配置和版本化数据以便回滚。若门槛未通过、模型不可用或前向不足，继续影子模式并报告差距，不宣称正式替换完成。

## 展示验收

- 有效候选只包含当日符合源 V4 条件且评分 ready 的 T1/T2，组内排序与源实现一致。
- 显示模型状态及版本、预测指标和数据日期；fallback/not_scored 及其原因可见且不混入排名。
- 无新信号、数据不足、结构观察和旧版观察分别可辨；盘中或缺少收盘证据时不显示为已确认。
- JSON、HTML、Markdown 对同一输入的分组、排序、状态一致；旧版快照和跟踪仍可读取，V4 与旧版本互不串用。

## 测试与切换门槛

- 迁移源仓 `tests/strategies/test_v4_algorithm.py`、`test_v4_scan.py`、评分及 pipeline 相关测试；补充目标扫描、展示、快照和跟踪集成测试。覆盖未来数据不变性、过期事件、T3、缺失行情/证据、无信号、节假日、停牌、重复运行、缺失/损坏/过期模型、冷启动及样本不足。
- 检查旧 JSON 合同和 golden 差异；实际修改 Python 后运行 `python3 .claude/skills/stock-trend/tests/test_stock_trend.py` 与 `python3 .claude/skills/stock-trend/tests/test_golden.py --diff`，逐项审查预期数值变化，不为消除失败而重生成快照。
- 回测先冻结确认日的实际可执行买入时点与价格、持有交易日计数、3% 止损、结构破坏和退出价、第五交易日退出、T+1、费用及未成交处理；确认日收盘成交不能直接假定可执行。
- 切换要求：跨仓固定样本一致、完整链路与展示测试通过、模型与数据有效、冻结的历史和前向门槛均通过，且旧版切回经过演练。任何一项不满足即维持影子模式。

## 风险及处理

- **算法覆盖变化：** V4 只处理当日新确认，旧观察状态单列保留，避免错误宣称全量替换。
- **模型不可用或漂移：** 输出显式状态，记录代码与模型指纹；不降级成伪造的 V4 分数。
- **数据口径或未来信息：** 固定同源样本并测试 point-in-time 特征、收盘证据和历史交易约束。
- **研究效果未达标：** 先冻结量化门槛和成交假设，未达标不切默认；迁移一致性与策略有效性分开验收。
- **长期维护：** 实施时确定单一算法维护源和同步方式，用跨仓黄金样本发现版本漂移。
