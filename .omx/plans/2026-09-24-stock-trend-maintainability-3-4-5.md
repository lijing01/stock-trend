# Stock Trend 维护性改进计划：模块边界、异常降级、Skill 文档

状态：仅计划，未实施。范围对应 2026-09-24 评审中的第 3、4、5 项。

## 目标与不变量

- 降低扫描主文件、异常降级路径和 `SKILL.md` 的修改与排障成本。
- 保持 CLI 参数、退出码、stdout JSON、MD/HTML 内容、正式推荐分桶/排序、快照及缓存语义不变。
- 保持数据源故障时已有的降级策略；保留人工审核、数据时效和免责声明约束。
- 不引入依赖，不批量迁移包结构，不顺带修改评分算法或报告文案。

依据：`scripts/scans/daily_candidates.py` 约 5,482 行，其中 2536–3022、4191–5032 行集中输出构造；`scripts/scans/stock_scanner.py` 约 3,762 行，其中 300–498 行是证据/缓存辅助、1194–1647 行是数据源获取；`SKILL.md` 为 402 行，包含多个独立工作流。

## 阶段 0：冻结行为与接口（所有代码变更的前置条件）

1. 列出外部可见契约：`daily_candidates.py`、`stock_scanner.py` 的 CLI 帮助、退出码、JSON 顶层字段、报告路径与文本、推荐快照，以及 `SKILL.md` 中的命令与安全规则。
2. 记录函数导入兼容面。`tests/test_daily_candidates.py` 直接导入 `generate_report`、`_generate_html`、`build_json_output`，并 patch `pick_hot_sectors`、`scan_sectors`；`tests/test_stock_scanner.py` 直接调用并 patch `_fetch_kline`、`_fetch_capital_flow`、`_fetch_fundamental`。迁移后原模块名称必须仍可导入、可 patch。
3. 先为缺少覆盖的实际边界补针对性回归样例：同一冻结输入的 JSON、MD、HTML；数据源超时/解析失败/缓存回退；`SKILL.md` 命令所指脚本存在。使用既有测试框架和 fixture，避免联网或读取 `reports/`。
4. 记录基线执行结果；若现有测试因外部条件失败，标明失败项并暂停依赖该断言的迁移。

验收：形成可复现的基线清单；每个后续阶段有明确的前后对比项。实施时，每次修改 `scripts/` 下 Python 文件后均执行 `AGENTS.md` 规定的 `test_stock_trend.py` 和 `test_golden.py --diff`，不为通过测试而重生成 golden。

## 阶段 1：Skill 文档分层（问题 5；可独立执行）

文件所有权：`SKILL.md`、新建的 `references/*.md`、必要的文档链接检查；不触碰 Python 实现。

1. 保留 `SKILL.md` frontmatter、触发范围、通用时效/联网规则、路由表、通用免责声明和每个工作流的入口摘要。
2. 将 ETF 扫描/回测（现 32–90 行）、今日推荐/候选（108–206 行）、每日复盘（207 行起）和个股 Step 1–4（241–394 行）详细说明分别移动到一级 `references/` 文件。主文件用相对链接直达，避免多级引用链。
3. 将机器专属 Python 解释器路径（现 12、21、113 行）放入本机运行说明；主文档写“Python >=3.10，使用当前环境中满足条件的解释器”。保留本环境可执行命令作为本机示例，不能误删实时接口的代理/沙盒契约。
4. 对照迁移前后检查每条命令、参数、字段、数据资格门槛、人工审核规则和免责声明逐项存在且语义一致；检查所有相对链接和脚本路径。

验收：`SKILL.md` 每个路由都能在一级引用中找到完整操作说明；frontmatter 与 discovery link 有效；文档中所有现行约束均有且只有一个规范位置；任何 CLI 或业务决策均未改变。此阶段只需文档/链接核验。

## 阶段 2：异常降级梳理（问题 4；先审计，再小批修改）

文件所有权：`core/source_health.py` 与选定的单个调用点；一个批次只由一个执行者编辑同一文件。

1. 建立异常清单，逐处标出：预期外部故障、输入/格式错误、可选副产物失败、顶层保护。优先审查 `daily_candidates.py:1943` 的排行获取、`:5258–5269` 的新闻影子层，`pipeline/runner.py:45–51` 的 JSON 读取，以及 `stock_scanner.py` 的数据源获取。记录当前返回值、降级标记和是否允许继续推荐。
2. 复用 `core/source_health.py:93` 的 `classify_failure` 和 `:129` 的 `live_attempt(error_type=...)`；先补异常类型与缓存回退的回归样例，再逐个调用点缩小可预期异常捕获。外层确有必要的兜底保留，用于维持当前降级结果。
3. 对静默失败增加模块级 debug 诊断，默认配置下不新增 stdout/stderr 行、不改变报告或 JSON；诊断记录来源、阶段、异常类型，不记录密钥或完整请求参数。若需要改变现有 `error_type` 证据字段，单独列为可观察契约变更并先评估快照影响。
4. 每改完一个调用点，比较正常、超时、无效 JSON、缓存可用/不可用五类冻结场景的返回结构与推荐结果。通过后再处理下一个。

验收：被处理调用点的预期外部失败仍走原降级路径；程序性错误有可启用的定位信息；默认 CLI 输出、正式决策、快照不变；没有新增裸 `except Exception: pass`。

## 阶段 3：拆分大文件（问题 3；按边界串行）

文件所有权：一次只迁移一个函数组；`daily_candidates.py` 和 `stock_scanner.py` 各由单一负责人编辑。新模块放在已有 `reporting/`、`core/` 或 `analysis/`，不建立新的框架层。

1. 先迁移 `daily_candidates.py` 中无网络/写入副作用的报告格式化函数，例如 `_signal_text`、`_append_candidate_table`、`_phase_d_lps_shadow_markdown` 和 `_html_candidate_rows`。排除 `save_observation_pool_artifact` 等写入函数。在原模块保留同名转发函数或导出，确保现有测试导入路径、patch 点、签名和调用顺序不变。先迁 Markdown，再迁 HTML；`generate_report`、`_generate_html` 和 `build_json_output` 作为稳定入口最后处理。
2. 再迁 `stock_scanner.py` 中无网络/写入副作用的证据与缓存判定函数，例如 `_cache_status`、`_evidence_status`、`_cache_verdict`、`_payload_validation_reasons`、`_validate_kline_cache`。排除 `_cache_fetch`、`_evidenced_fetch` 等实际抓取协调函数；保持 `_fetch_*` 留在原模块，并逐一核对 monkeypatch 与模块全局变量引用。
3. 最后才评估带 I/O 的抓取协调函数（约 1194–1647 行）和 `daily_candidates.py` 的主流程。只有纯函数迁移已验证、依赖图清晰时才开下一批。若迁移需改变缓存键、重试顺序或快照时点，该批退出本“功能不变”计划，另立变更。
4. 每个函数组作为独立、可回退的变更批次，完成针对性测试和两道强制质量门后才开始下一组。不要按行数目标做大规模搬迁。

验收：原模块导入 API、CLI 参数/退出码、冻结输入 JSON/MD/HTML、推荐分桶/排序和快照与基线一致；被迁移函数只保留一个实现；调用依赖方向保持 `scans -> core/analysis/reporting`，无循环导入。

## 并行与交接

- 阶段 0 由一名负责人完成基线；阶段 1 的文档迁移与阶段 2 的异常清单可在阶段 0 后并行。两者不共享源文件。
- 阶段 2 的代码修改与阶段 3 的拆分都触及扫描文件，应按文件串行，先完成异常批次再拆分对应文件，或为两个文件分别安排不重叠负责人。
- 每批交接物：改动文件、旧/新函数位置、保留的兼容入口、测试结果、golden 差异、未处理的异常清单。下一批以交接物为基线。
- 任一阶段出现正式推荐、报告、快照或缓存语义变化，立即停止该批并回退该批改动，先判断是否需要单独的功能变更计划。

## 主要风险

| 风险 | 控制办法 |
|---|---|
| 函数搬迁导致 mock/patch 点失效 | 保留原模块同名入口；针对直接导入与 patch 的现有测试做前后对比。 |
| 更窄异常捕获让既有降级变成报错 | 每个调用点先列出实际异常类型；保留外层兜底；验证缓存回退和退出码。 |
| 文档拆分丢失强制约束 | 建迁移核对表，逐项检查原文中的时效、数据资格、人工审核、免责声明和命令。 |
| 默认诊断改变机器可读输出 | debug 诊断默认关闭，不写 stdout；任何证据字段变化单独审查。 |

## 完成判定

三个阶段各自满足验收标准；全部 Python 批次通过两道强制测试及对应专项回归；golden 无未经解释的差异；文档链接与命令引用有效；工作树仅含计划内文件。该计划不要求消除所有宽泛异常或将两个主文件拆到特定行数。
