# K 线单一权威缓存修复计划

日期：2026-09-10。状态：待实施；本次只交付计划。

## 目标与范围

统一 K 线读取、成功写入和容量清理入口；同一行情序列只保留一份受管理的完整数据。保持 CLI 的 JSON 输出和分析输入契约，保留 cache-only、强制刷新、过期数据诊断行为。不引入数据库或第三方依赖，不改变评分、买点和历史保留长度，不做逐日增量拼接。

此前建议直接将 `{code}/kline.json` 作为权威缓存需要修正：该路径没有交易所、周期和复权维度，适合作为旧输出路径，不能直接承担新缓存身份。

## 已确认依据

- `scripts/core/cache_utils.py:48,81`：通用缓存按 key 保存根目录 JSON，直接覆盖写入。
- `scripts/fetchers/kline_eastmoney.py:369,528`：先保存共享缓存，再写 CLI 输出，扫描器传入的输出路径也位于缓存目录。
- `scripts/scans/stock_scanner.py:1081`：直接读取 `{code}/kline.json`，验证日期和有效条数；没有以完整序列身份寻址。
- `scripts/pipeline/runner.py:221`：固定输出 `kline.json`，日线与周线共用同一输出路径。
- `scripts/fetchers/capital_flow.py:183`：资金流估算也直接依赖旧路径，必须一起接入。
- `scripts/fetchers/kline.py:306`：缓存 key 不包含请求日期范围；东方财富入口的 key 同样不包含 `--lmt`，命中时没有核验要求的历史长度。
- `scripts/core/cache_utils.py:124`：清理只处理根目录 JSON，按写入时间排序，不能称为按访问时间的 LRU。
- 上一轮本地统计：两类 K 线分别约 168.4 MiB、161.2 MiB；这是文件总量，未逐份比对，不能直接承诺释放其中任一数值。

以上路径相对于 `.claude/skills/stock-trend/`。

## 设计决定

增加专用 `core/kline_cache.py`，对外集中提供读取、验证、发布成功结果和受限清理能力，复用现有日期/质量验证工具。推荐路径：

`.cache/stock-trend/klines/v1/{ts_code}/{asset}/{freq}/{actual_adj}/{source}.json`

一个身份对应一个完整序列文件，包含数据及元数据。不同来源属于不同序列，不能相互拼接；来源选择保留现有调用链的回退优先级。使用完整证券代码，实际复权必须由来源能力确定，不能只把请求参数写入标签。

请求条数和起止日期属于覆盖要求，不作为独立文件维度，以免重新产生重叠副本。元数据包括 schema、完整身份、fetched_at、最新行情日、覆盖范围和可用条数。读出时按请求裁剪；覆盖不足明确 miss。不得仅凭首末日期声称中间数据完整，新股/停牌不能简单要求自然日连续。

第一版继续整段刷新。前复权历史可能修订，因此禁止把不同抓取批次直接追加为同一序列。新结果若缩短覆盖，不覆盖较长的成功缓存：优先按原覆盖重取；无法满足时本次结果仍可输出，但不晋升为权威缓存。

盘中数据和已收盘数据分别判定有效性：使用当前市场交易日及交易时段，盘中保留短 TTL，日期覆盖仍为必要条件；周线未完成期间需要刷新。沿用已有交易日工具，明确港股日历不足时的降级证据。TTL 过期只影响使用资格，不等于立即删除历史数据。

CLI 显式 `-o` 继续生成独立导出文件。导出属于调用结果，不参与缓存命中，也不算受管理缓存副本。默认管道内部直接传递权威文件路径；无显式导出需求时不再长期保存 `{code}/kline.json`。不得把可写的旧路径软链接到权威文件，否则错误输出可能穿透覆盖好数据。

## 实施顺序

### 1. 建立回归基线和调用清单

修改前补充有行为价值的固定夹具：扫描器命中不启动子进程、cache-only 不联网、失败仍能报告旧行情日期、CLI `-o` 可独立读取。覆盖上述文件及 ETF/维科夫回测、图表读取链。区分应保持的行为和本次故意修正的身份混用/覆盖不足行为。先运行基线，再修改脚本。

### 2. 实现专用缓存及验证契约

实现完整身份和覆盖要求验证、原子发布及失败保留。同目录临时文件写完后原子替换；发布前短锁保护“重新读取、比较、替换”，网络抓取不持有文件锁。较旧行情不得覆盖较新缓存，较晚失败不得覆盖成功文件。实际复权无法确认的旧记录禁止自动晋升；数据源不支持请求复权时明确失败或走既有可满足来源。

### 3. 接入生产者与消费者，停止内部双写

依次接入 `fetchers/kline.py`、`fetchers/kline_eastmoney.py`，然后 `scans/stock_scanner.py`、`pipeline/runner.py`、`fetchers/capital_flow.py`。保留 JSON `{meta,data}` 契约和显式导出；扫描器从统一入口读数据，不再以输出文件是否存在作为刷新成功依据。港股成功分支也经统一发布入口。清点并更新测试夹具里的旧路径假设及相关技能/规格说明。

### 4. 兼容迁移和专用清理

提供 dry-run 盘点：列出旧根目录 `kline_*.json` 和已知证券目录 `kline.json`，报告数量、大小、身份冲突及不可迁移原因。优先读取新缓存；只在没有可满足请求的新数据时尝试经过验证的旧缓存，保留原始抓取时间，不能借迁移刷新 TTL。多个候选按身份、质量、行情日期和覆盖要求选择，冲突无法消解则保留并报告。

迁移发布后重读验证数据与元数据，再将对应旧文件移至专用迁移备份目录；不移动其他分析文件。备份与活跃缓存分别统计，备份存在期间不得声称磁盘空间已经释放。旧备份不参与自动回退，防止已淘汰数据被不断重新导入。保留一轮验证窗口，备份删除作为单独、明确列出目标的后续动作。

K 线专用清理只管理新命名空间，预算独立且可配置；第一版沿用写入时间的最旧优先策略并正确命名，不增加每次读取写访问时间的复杂度。超过预算后清至预算的 80%，排除临时文件、锁、迁移备份和本轮正使用的文件。通用清理保留其他缓存行为，由公共 K 线入口限频触发专用清理，避免仅 runner 执行清理。通用 clear 和 K 线 clear 的范围必须明确且有测试。

## 验收标准

1. 同一身份连续运行扫描器与管道，仅存在一个活跃权威序列；默认流程没有新旧两套完整写入。
2. 显式 `-o` 生成独立合法 JSON；修改该导出不能影响权威缓存。
3. 日/周线、市场、资产类型、实际复权、来源均不能误命中；250 根请求不能由仅 60 根缓存充当完整命中。
4. 日期范围请求按范围裁剪，范围不足 miss；较短刷新不缩短已保存覆盖。
5. 盘中同日过期数据触发刷新；过期、错误、缺字段数据不能被标为 fresh；cache-only 不启动网络或子进程。
6. 失败刷新、进程中断及同身份两个进程竞争写入后，权威 JSON 仍可解析，且最后一份成功数据没有被错误/较旧数据覆盖。
7. 迁移重复执行幂等；无身份依据、日期冲突或损坏文件不自动晋升；迁移不改变原抓取时间。
8. 小预算夹具能证明超过上限后回落至 80% 目标；无可淘汰文件时明确报告未达标。非 K 线文件及备份字节完全不变。
9. 固定有效输入的技术评分、维科夫结果和报告数值不变；仅有事先明确的缓存诊断字段变化。

## 风险与回退

- 身份收紧可能降低旧缓存命中率：优先验证可确定记录，未知记录保留，不伪造实际复权或来源。
- 并发淘汰可能影响仍通过路径读取的分析：本轮使用文件需被保护，测试覆盖读取消费阶段；显式导出独立于缓存。
- 旧脚本仍绕过统一入口：实施前后搜索路径依赖，使用端到端夹具证明 scanner、runner、capital-flow、回测链均已接入。
- 回退先停用新入口，再从迁移备份恢复原路径；恢复前检查目标文件，不能覆盖迁移后用户生成的新输出。旧备份删除前保持可回退。
