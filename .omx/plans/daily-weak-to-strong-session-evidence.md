# 日线弱转强：盘中计算与盘后收盘确认

## 目标和范围

盘中以当天可用的日线快照计算形态并标记临时；盘后先核实目标交易日的 K 线已收盘，再判断收盘形态。区分“可以计算”和“收盘确认”，保留现有正式推荐、市场及板块门槛，避免盘中结果被误认为正式推荐。覆盖今日推荐中的日线弱转强 V1、关联 V2、汇总与报告；不改变形态参数或另加盘中交易策略。

## 实施步骤

1. 梳理时段与证据：检查 `scripts/scans/stock_scanner.py` 的 `_kline_close_confirmation` 和扫描调用，以及既有交易日历、扫描时段策略。统一使用上海时区与交易日历判定盘中、午休、盘后及非交易日；非交易日按目标最近交易日数据的收盘证据判断，不以当前时间直接证明历史 K 线已收盘。明确数据日期、获取时间、来源、收盘标志；复用现有来源白名单及 15:10 规则，核对其是否适用于历史缓存，无法证明时降级。
   - 盘中每次生成报告时，主动向行情源刷新扫描范围内各标的的最新日线 K 线，取得包含目标交易日当时价量的快照；历史日线可复用有效缓存，但不得仅因缓存包含当天日期就把旧快照当作最新数据。沿用现有取数限流、去重和失败诊断，记录数据源及实际获取时间。
   - 为盘中快照定义并在实现前核实与现有取数策略兼容的时效阈值；刷新失败或快照超时效时明确标注数据过期或获取失败，不纳入以最新盘中数据计算的已评估数量，也不把旧数据冒充实时数据。停牌及当日无有效行情单独标注原因，不伪造当天 K 线。
2. 修改 `scripts/analysis/daily_weak_to_strong.py`：将数据可计算性与收盘确认拆开。历史日线按已完成日回放，盘中当天快照用于计算当日全部适用状态，包括缩量、回调和临时突破，统一标记为盘中临时；不得将当天的临时状态写成历史已确认事件。盘后仅当目标日期和收盘证据有效时使用当天最终日线作收盘判断；未确认时不把临时 K 线当作收盘结果，提供明确原因。保留缺少目标日、历史不足、复权不明、日历不完整等真实数据缺陷。
3. 检查并同步 `scripts/analysis/daily_weak_to_strong_v2.py` 和对应扫描入口：对计算状态、确认状态及 V1 输入依赖采用一致语义；审查快照和跟踪（`scripts/core/weak_to_strong_snapshot.py`、`scripts/analysis/weak_to_strong_followup.py`），临时结果不可污染正式确认历史；兼容已保存的旧版数据和 JSON 消费方，必要时增加版本或可选字段。
4. 修改 `scripts/scans/daily_candidates.py` 的 `build_weak_to_strong_output` 和 `scripts/reporting/weak_to_strong.py`：按计算结果分组，盘中可计算的缩量、回调、突破分别可见且均有临时标识；正式收盘确认仅来自有效的收盘证据。汇总定义为扫描总数 = 已评估 + 数据不足（互斥）；已评估分为盘中临时、盘后已确认及其他确实完成评估的状态，收盘未确认单列，避免重复计数；保留逐股诊断和来源/更新时间。正式分桶及限制保持独立。
5. 更新 `references/daily-weak-to-strong.md`，记录字段、交易时段、统计口径和降级原因；按实际兼容性调整相关 schema 和报告说明。

## 验收与验证

- 可用当天快照的交易时段内，缩量、回调、突破均按当天数据评估，标记盘中临时，计入已评估，不计入数据不足；只要存在其他真实数据缺陷仍计数据不足。盘中不可产生收盘确认或正式推荐资格。
- 盘中生成报告触发最新 K 线刷新；同一交易日已有旧缓存时仍触发刷新，展示实际来源和获取时间。模拟刷新成功、失败、超时、过期缓存和停牌，验证旧快照不会被标为最新或计入盘中已评估。
- 同一标的盘后具备目标日期及可信最终收盘证据时，按最终 K 线重新计算并可确认；盘后不具备证据时显式显示收盘未确认，不能生成收盘确认或将旧日价格冒充当日数据。
- 覆盖 09:30、午休、15:00、15:10 边界、非交易日、数据源明确未完成、数据源明确已完成、缓存获取时间过期或来源不可信、历史 K 线缺失/日期不符/复权不明、交易日历缺失、停牌，以及无形态的 WAIT、结构失效等情况。盘中成交量为截至快照的累计量，维持同一口径并标识临时，不推断全日量能。
- 验证同一股票由盘中临时转为盘后确认或消失，历史事件与跟踪不会将盘中临时结果固化为确认；V1、V2、JSON、HTML/Markdown 的标签与数量一致，汇总满足总数等式。
- 执行 `tests/test_daily_weak_to_strong.py`、`tests/test_daily_weak_to_strong_v2.py`、`tests/test_weak_to_strong_integration.py`、`tests/test_weak_to_strong_reporting.py`、`tests/test_stock_scanner.py` 及快照/跟踪相关测试；再执行仓库要求的 `python3 .claude/skills/stock-trend/tests/test_stock_trend.py` 和 `python3 .claude/skills/stock-trend/tests/test_golden.py --diff`。不为消除失败而直接更新 golden。

## 风险与约束

- 时钟晚于收盘不等于数据已更新：先核对数据日期、来源标志和实际抓取时间；证据冲突优先降级。15:10 为现有规则，需覆盖其来源限制与跨日情况。
- 盘中量价随时间变化，临时形态可能消失，报告必须标注快照时间及收盘后复核。
- 不同状态字段、旧快照及下游消费者可能依赖现有 `evidence_status`；先梳理所有使用点，采用兼容演进并通过回归测试验证。
