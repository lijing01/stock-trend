# 每日复盘在会话中展示摘要

## 目标与范围

执行“今日复盘”后，最终回复不能只列出评分、成交额、涨停数和文件路径；应在会话中提供一份可读的复盘摘要，同时保留完整 Markdown/HTML 报告链接。改动只调整 `stock-trend` skill 的交付契约，不改变市场数据采集、评分、缓存、报告生成或交易规则。

现有完整报告由 `.claude/skills/stock-trend/scripts/analysis/market_regime.py:809-906` 生成；其 Agent JSON 已提供需要的字段（`build_agent_output`，同文件 `1132-1155`）。因此不需要新增 Python 摘要逻辑，也不需要更改报告格式。

## 验收标准

- 每次 `/daily-review` 成功后，最终回复包含“今日复盘摘要”，而非仅文件路径和四项数字。
- 摘要明确标示依据日、收盘/盘中临时状态、市场评分/档位/操作建议；`stale_note`、`intraday_note` 或数据资格异常存在时必须一并醒目展示。
- 摘要至少覆盖市场广度与情绪（涨跌家数、成交额、涨停/连板）、最强/最弱板块、持仓异常或关键观察，以及不超过三条的明日 if-then 计划。
- 数据缺失时显示“数据缺失/未提供”，不以 `0` 或推测内容替代；无持仓时明确说明；正常持仓不重复整张报告表。
- 完整 Markdown/HTML 仍以可点击本地链接交付，且固定免责声明保留。
- 评分算法、`market_regime.json`、历史记录、HTML/Markdown 文件内容和 CLI/JSON schema 均无变化。

## 实施步骤

1. 修改 `.claude/skills/stock-trend/SKILL.md:237-250` 的 `/daily-review` 输出说明，新增“最终回复格式”契约。指定以脚本结果或 `--json` 的 `regime`、`components`、`amount_yi`、`zt`、`top_sectors`、`bottom_sectors`、`holdings`、`plan` 为唯一事实来源。
2. 在该契约中给出紧凑 Markdown 模板：市场结论、市场宽度/情绪、板块强弱、持仓重点、明日计划、报告链接与免责声明。限制只提炼关键数据，不复制完整五项评分表、持仓全表或全文报告。
3. 写入分支规则：盘中或非当日数据优先显示临时/过期说明；`data_quality=partial`、缺失组件或非 `scorable` 时标明限制；字段为空时用“未提供”；持仓段只显示跌破止损、MA20/MA5 触发、数据不可用等需要行动的项。
4. 使用已生成的 daily-review JSON/固定测试上下文做一次人工渲染检查，确认该模板能表达强势、中性、弱势、盘中和无持仓五种情形，且不会杜撰行情字段。

## 验证

- 对 skill 文本运行 `git diff --check`，并人工核对模板覆盖全部验收字段。
- 运行一次 `market_regime.py --no-refresh --json`（不刷新行情）确认所引用字段均已在 Agent JSON 中存在；不修改 Python，因此不触发 Python 文件变更后的两项质量门禁。
- 在完成后的实际交付中，检查最终回复同时含摘要、两份报告链接和“本报告仅供学习参考，不构成任何投资建议。股市有风险，投资需谨慎。”。

## 风险与处理

- **摘要与完整报告不一致**：只从同一次命令的 JSON/标准输出提取，不从旧缓存或手工猜测补数。
- **摘要过长又重复报告**：限定为关键指标、Top/Bottom 板块、异常持仓和最多三条行动条件。
- **盘中数据被误称为收盘结论**：`intraday`、`intraday_note` 和 `stale_note` 优先于任何操作性表述。
