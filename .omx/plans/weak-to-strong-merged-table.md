# 日线弱转强与上一交易日信号跟踪合表

## 目标与口径
- v1 的 Markdown、HTML 合并为一张表；v2 研究版、正式推荐分桶和信号判定不变。
- 同一证券同一周期合并为一行，同时保留当日形态和跟踪状态、原信号日、依据及数据资格；仅出现在任一来源的记录也保留。不同周期不能误合并，需明确标识。
- 名称/代码后显示“跟踪 N 次”。N 指该信号周期从首次进入跟踪起，按不同交易日产生跟踪记录的次数；首次跟踪为 1，同日重复运行不增加，待复评也计一次，失效当日计入。无法验证历史时显示“跟踪次数未知”，不得猜测。
- 排序先按需处理程度：失效、待复评、收盘确认/跟踪增强、缩量待突破/跟踪延续、结构有效回调、盘中临时；同组保留原形态质量排序，跟踪记录用原信号日期和代码作稳定兜底。盘中临时与数据不足须显著标注，不能被排序解释为交易资格。

## 实施
1. 检查 `scripts/scans/daily_candidates.py` 的跟踪基线和快照读取、`scripts/analysis/weak_to_strong_followup.py` 的周期关联及快照合同，确认旧快照、同日重跑和周期切换的处理方式。为跟踪次数增加可审计的持久化来源；优先从可验证的连续快照恢复，缺口保留未知，不用自然日或原信号日差值代替计数。周期升级保留或重置计数须按周期 ID 判断，信号日期变化不单独触发重置。
2. 在 `scripts/reporting/weak_to_strong.py` 建立只供展示的统一行模型，以证券代码和周期证据匹配；保留来源、状态、原因、H/L、量比、收盘强度和正式限制，缺失字段显示“—”。同证券不同周期或无法可靠关联时分别显示并说明，避免隐藏失效或待复评。统一排序供 Markdown 与 HTML 共用，保留诊断和跟踪基线/缺口提示。
3. 更新 `references/daily-weak-to-strong.md` 与 `references/today-and-candidates.md`，说明合表、排序、跟踪次数定义和观察性质。更新相关报告测试与集成测试，不改变既有正式推荐数据或新闻层。

## 验收与验证
- 两种报告均恰有一张 v1 表，行顺序一致；同周期重叠只出现一次，新信号、仅跟踪、失效、待复评及不同周期均不丢失。
- 测试首次与连续跟踪、同日重跑、周末/节假日、待复评、失效、周期更换及旧快照/历史缺口；次数不可验证时显示未知。
- 覆盖盘中、数据不足、空数据、HTML 转义、Markdown 竖线、板块信息和排序稳定性；原始 JSON 及正式推荐资格保持兼容。
- 运行专项报告、跟踪、集成测试；按仓库要求运行 `bash tools/python.sh .claude/skills/stock-trend/tests/test_stock_trend.py` 与 `bash tools/python.sh .claude/skills/stock-trend/tests/test_golden.py --diff`。不为消除失败而直接刷新 golden；逐项确认预期输出变化。

## 风险
- 现有跟踪基线没有次数，且原信号日期在缩量突破时会更新，不能仅以日期相减得出真实次数。旧历史缺口显示未知，避免虚构。
- 同股可能出现新旧周期，需保留失效/待复评证据；展示合并不应覆盖原始快照或改变交易判断。
