# 今日推荐参数抽取与历史评估计划

状态：计划，尚未实施。日期：2026-09-21。

## 目标与边界

把今日推荐实际生效的选股、评分、门控、分层参数集中为有版本的策略配置，并让线上推荐与历史评估调用同一套决策函数。历史评估既能对已有冻结研究快照做受限重排，也能在具备历史时点原始数据时重建完整生产链。研究结果只提出参数调整建议，不自动发布策略。

现有 `docs/six-factor-historical-replay-design.md` 是未跟踪的六维评分草案；本计划扩展到市场状态、板块与候选范围、质量门、买点奖励、排序和推荐分层，不修改该草案。

## 当前实现与缺口

- 统一入口 `bridge/run_today.py:173` 调用 `scans/daily_candidates.py:4306`；后者负责扫描、分层、快照和报告。正式模式固定扫描前 120 个板块，探索模式使用 60/20/120 的逐步扩池参数（`daily_candidates.py:81-83,2023-2096`）。
- CLI 默认 `top=30`、`min_candidates=20`、`min_score=50`、新闻回看 14 天（`daily_candidates.py:4308-4343`）。市场分 60/80 决定观察/等待/可执行，资金组件低于 35 另需板块资金证据，推荐上限为 0/2/5（`daily_candidates.py:3326-3380`）。
- 六维评分权重在 `scans/stock_scanner.py:1949`；质量权重与最低覆盖率在 `core/recommendation_quality.py:6-7`；买点奖励和资格门、排序、分桶分别在 `daily_candidates.py:188-219,316-365,2268-2290,3440-3545`。部分阈值散落在板块、市场环境、维科夫及质量模块，尚无一份可枚举、可校验的完整策略合同。
- 研究快照保存部分参数、真实选择范围、候选和结果（`daily_candidates.py:4550-4595`，`core/candidate_research_snapshot.py:133-257`），但 `decision_at` 固定为 15:00 基准，不证明各来源当时已知；缺 `known_at` 时不能视为严格历史时点输入。
- `backtesting/recommendation_experiments.py:245-281,686-1085` 已复用生产选择/分类函数，支持 walk-forward、显式日历、validation/holdout 和 60 交易日 purge；它依赖已保存的候选人口，无法评估改变扫描范围、六维原始评分或上游板块门槛后的完整候选集。
- `analysis/recommendation_attribution.py:1002-1378` 与 `core/evolution_contract.py:13-55` 可复用前向收益、沪深300基准、成熟窗口与评估合同。ETF 和维科夫回测仅提供截断输入的实现范式，不能替代今日推荐生产链回放。

## 参数合同设计

新增 `core/recommendation_strategy.py`，定义不可变、可序列化、可校验的 `RecommendationStrategyConfig`（例如 `today-recommendation/v1`），并生成 canonical JSON 与内容 hash。盘点范围是 `run_today → daily_candidates → stock_scanner/market_regime/sector_data/recommendation_quality/Wyckoff/registry` 调用链中所有会改变股票池、评分、资格、顺序或分桶的值；每项记录位置、默认值、单位、适用模式、输入、覆盖优先级、是否可实验、是否影响候选宇宙。每个现存硬编码值必须映射到策略字段或明确列为算法不变量/运行预算，并在盘点表中解释；不得遗漏后仍宣称“全部参数已抽取”。

| 组别 | 首批纳入的参数 | 历史评价方式 |
| --- | --- | --- |
| 扫描范围 | 板块最低热度 45、最少成分股 10（`daily_candidates.py:1719`）、主线/新兴连续天数 3/2 及持续性分 60/45（`daily_candidates.py:1274-1275,1488-1496`）、60/20/120 扩池、每板块股票上限、候选 Top N、最少候选数 | 必须完整历史重算；冻结 Top N 不可反推新增样本 |
| 六维评分 | 有维科夫时的 25/15/15/10/10/25 权重、无维科夫时的 30/20/20/15/15 权重，以及各维内部阈值（`stock_scanner.py:1949-1965`） | 原始历史数据重算；有完整逐维分的快照可做受限重排 |
| 数据资格 | K线/资金/基本面质量权重、70% 覆盖率、来源新鲜度、缺失/降级规则 | 仅在冻结证据足够时重放；未知时间一律无严格证据 |
| 市场与板块门 | 市场五维权重、60/80 档、资金背离 35、板块可执行与资金验证 | 历史市场/板块快照重算；不可用当前状态回填 |
| 买点与输出 | 维科夫确认/健康/时效门、1/3/2 买点奖励、最低分 50、0/2/5 推荐上限、稳定排序键 | 共用生产选择与分桶函数；安全门先保持硬约束 |
| 观察层 | 新闻 14 日回看和影子评分 | 单独评估影子层，不混入正式策略表现 |

有效配置按 `v1 默认值 → 截至决策日已发布的 evolution_registry 策略版本 → 本次 CLI 显式覆盖白名单` 合成；当前 CLI 未提供买点奖励覆盖，不能通过 CLI 绕过已发布版本。每层来源、发布版本、覆盖字段和最终 hash 都写入快照。历史日若无可信的发布版本记录，只能使用明确指定的冻结基线配置，不能读取当前发布指针来冒充历史配置。正式推荐要求维科夫买点，采用六维分支；无维科夫五维分支保留给通用扫描器，并在参数合同中显式区分，历史实验不能跨分支偷换基线。`--strategy-shadow` 是并列试验定义，不参与正式配置合成。研究配置与数据可见性、交易执行假设分开：`StrategyConfig` 只描述推荐决策；`InputManifest` 描述当时已知的数据与覆盖率；`EvaluationContract` 描述 5/10/20/60 日标签、基准、成本和入场假设。只允许显式的参数搜索空间；正式安全门可测量敏感性，但不得由实验输出自动放松。

历史输入采用本地 `data/history/v1/` 的 manifest + 分区 JSONL 或 SQLite，不新增依赖。定义交易日历、当日股票池及 ST/停牌/涨跌停状态、板块排行及历史成分、OHLCV/复权与公司行为、资金、按披露时刻版本化的财报、市场环境原始组件、基准价格的导入协议；每行至少含证券或板块标识、`data_date`、`available_at`、`known_at`、来源/版本和 payload，每个分区有行数、覆盖日、缺口与 SHA-256。新增 `backtesting/today_history_import.py` 作导入/校验入口：逐决策日输出必需数据集是否完整、可见时间是否合法、股票池与板块成分是否覆盖，以及可回放/不可回放日期和原因；缺必需分区的日期直接拒绝。第一步先盘点仓内可导入源；`sector_data.py:608-630,1326-1367` 的近期缓存不能直接充当完整历史成分/板块档案。若没有足够来源，完整回放阶段停在数据缺口报告，仅完成冻结快照实验和确定性 fixture，不伪造年度全市场结果。

## 实施步骤

1. **锁定现行行为与盘点参数。** 建立参数清单和少量冻结 fixture，覆盖强/中/弱市场、质量缺失、板块未知、买点失效、同分排序、正式与盘中模式。记录现行推荐名单、各维分、分桶、拒绝原因及快照 hash；先写回归测试，再改生产代码。
2. **抽取合同与纯决策层。** 将散落的有效默认值移入版本化配置，保留 CLI 显式覆盖并写入 `effective_config`。把 `build_recommendation_policy`、评分合成、质量资格、买点奖励、选择、分桶改为显式接收配置；网络抓取/缓存/报告仍由编排层负责。`run_today.py` 与 `daily_candidates.py` 均从同一配置加载；旧调用可在迁移期使用 v1 默认值。版本不认识或配置校验失败时拒绝正式输出。
3. **冻结完整输入与决策证据。** 扩展 `core/candidate_research_snapshot.py` 及 manifest，保存配置 ID/hash、代码版本、原始数据源版本与 `data_date/available_at/known_at/captured_at`、真实扫描板块和成员、所有进入评分范围的股票、排除原因及选择范围 hash。历史决策时刻必须晚于所使用收盘数据的实际可见时刻，不能沿用当前快照中作为基准的 15:00 字段来证明可见性；`run_today.py:86` 的 15:10 正式路由切换也不等于供应商数据已可见。缺时间戳记为 `unknown`，不得把抓取时间当成历史可见时间。旧快照逐字段验证：已有范围 codes/hash 的可保留已验证范围内重排资格；缺来源时间的标 `time_unverified`，不得进入严格历史重算。
4. **两级历史评估。** 先扩展现有 `backtesting/recommendation_experiments.py`：在相同冻结人口和配置下调用共用选择器，支持明确声明范围内的参数组与成对比较；范围改变、缺逐维输入、缺资格证据时拒绝重排。随后新增历史数据导入/校验器与 `backtesting/today_replay.py`，按每个决策日的历史股票池、板块成分、排行、行情、资金、财报披露和市场输入重新扫描、评分、门控并冻结研究快照，再交给同一评估器。先用 `tests/fixtures/today_replay/` 的跨财报披露、退市和板块变更微型数据集打通链路；真实数据覆盖合格后才跑年度样本。
5. **评估与输出。** 复用归因合同计算候选预测力与可执行模拟两个独立口径；前者按既有“下一交易日收盘至窗口收盘”的冻结样本口径，后者单列成交限制、T+1、滑点和费用。沿用现有 `recommendation_experiments.py:466-515,945-958` 的 discovery、三个 validation、holdout 与相邻分区至少 60 交易日 purge，并维持每个验证块的成对日期/成熟事件门槛，不用单个总体门槛替代。输出每组参数的日期数、去重事件数、覆盖率、不可比/拒绝数量、Top1/3/5、20 日主指标、5/60 日辅助指标、HS300 超额、分位/IC 和置信区间。日历、分区或成熟度不达现有门槛时标为 `continue_accumulating`，不作“参数优于基线”结论。
6. **小样本验收后扩大。** 先用微型 fixture 和一个覆盖合格的年度、每周重放与 Top 10 验证工程链路；单年周频样本只作烟测，不宣称通过多分区统计门槛。随后扩展到足以满足四道 60 交易日 purge 和各验证块最低样本数的历史区间，再锁定样本外比较。每次运行输出配置 hash、输入 manifest hash、评估合同 ID、代码版本和报告 hash，便于复现。

## 验收标准

- 相同冻结输入和配置，线上与离线输出的逐维分、质量分、排序、分桶、拒绝原因完全一致；重复运行结果 hash 一致。
- 在决策时点之后新增更好的价格、资金、财报、板块或新闻数据，过去的结果不变；`available_at` 与 `known_at` 都必须不晚于实际决策时刻，任一缺失或较晚就拒绝严格回放。公告披露前、未来成分股、盘中 provisional 均不能进入正式历史样本；复权因子在信号计算时也需按当时版本截断，前向收益则使用评估合同声明的统一口径。
- 更改扫描范围但只提供旧 Top N 快照时，评估返回明确 `scope_unverified` 或 `unsupported_counterfactual`，不产生收益比较。
- 配置校验失败、时间未知、历史成分缺失、窗口未成熟均有明确排除数量和原因，不静默填充。
- baseline 与试验组使用同一日期、可投资人口和评估合同；holdout 不参与调参，重叠窗口按交易日块处理；现有每个验证块的样本门槛不得降低。
- 旧 `run_today.py --json` 和 `/candidates` 默认行为保持兼容；正式推荐不会因为研究结果自动改变权重、门槛或发布指针。

## 风险与验证

- **历史数据偏差**：当前成分、最新修订财报、无 `known_at` 的来源会制造未来函数。按可见时刻与版本过滤，缺证据时降低可用样本而不猜测。
- **仅重排的误用**：快照实验不能证明扫描范围或原始评分阈值。报告强制标明 `frozen_population_replay` 或 `full_point_in_time_replay`，并列出可评估参数。
- **生产行为漂移**：抽取配置时逐组替换，先固定 fixture，再比对正式 JSON/研究快照；保留稳定排序和原因码。
- **选择偏差**：预先冻结候选参数网格、主指标和 holdout 区间；报告全部尝试与样本量，不凭单次最优值调权。

验证顺序：定向纯函数/防泄漏/一致性测试 → `python3 .claude/skills/stock-trend/tests/test_stock_trend.py` → `python3 .claude/skills/stock-trend/tests/test_golden.py --diff` → 静态检查及一个离线年度重放。使用 Python 3.10 解释器；金样例只有确认预期输出变化后才更新。第一阶段停止条件是生产与冻结重放一致、缺失证据安全拒绝、两个质量门通过；第二阶段停止条件是完整历史回放可复现并能清楚区分样本外证据强弱。

本计划是工程研究方案，仅供学习参考，不构成投资建议。
